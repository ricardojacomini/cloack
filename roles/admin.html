Admin — cluster / DevOps operator running start.sh and Ansible

Who you are + scope

You operate the Portal stack on physical hosts: your laptop, the bare-metal validation host that builds and publishes images, and the production host. You run ./start.sh deploy / start / publish / promote, you ship images to GHCR, you run ansible-playbook for the bare-metal Slurm cluster install, and you own the rotation of the GHCR PATs.

You are the only role that needs read-write access to GHCR. You typically also have is_superuser=True in ColdFront: for the cluster ops Django side read superuser.md. For helpdesk work see staff.md. You authenticate the same way every other user does (user.md).

Quick start

Four recipes you will run most days. Server hosts keep the repo at /opt/cloack; the laptop wherever you cloned it.

1. Laptop: full local stack with test data

./start.sh deploy dev -y --paid-accounts   # full clean + reseed dev stack
bash scripts/verify-deploy.sh              # 15 checks; exit code = number of red checks

Use this when you want a clean known-good state. It wipes named volumes and reseeds 4 test users (ext-staff, ext-user, orgb-staff, orgb-user, password 123). deploy is only ever run with the dev argument on a host whose coldfront.env says CLOACK_ENV=dev; on CLOACK_ENV=prod hosts start.sh refuses the dev compose file.

2. Build, publish, validate and promote on the validation host

ssh <validation-host>
cd /opt/cloack
git pull origin dev               # clean tree: publish refuses a dirty one
./start.sh rebuild                # local build of every cloack/<svc> image
docker images | grep ^cloack/       # prune stale cloack/* images: publish pushes ALL of them
./start.sh publish --check        # dry run: the retag plan
./start.sh publish                # docker push :dev + :sha-<git-short>
./start.sh start --from-ghcr dev  # run the PUBLISHED images, no build
bash scripts/verify-deploy.sh     # mandatory pre-flight
./start.sh promote                # :dev -> :prod + :rc-<UTC>

promote runs verify-deploy.sh as a pre-flight gate by default; use --skip-verify only as an emergency override. Never run ./start.sh deploy --from-ghcr: it is hard-refused, because the validation and production hosts must never be populated with test data.

3. Deploy on the production host

ssh <production-host>
cd /opt/cloack
git pull --ff-only origin dev                # configs, templates, migrations
./start.sh start --from-ghcr prod            # docker pull :prod, no build
bash scripts/verify-deploy.sh
docker restart coldfront qcluster            # when tasks.py or base.py changed
./start.sh helpdesk restart                  # helpdesk code is staged from the repo, not baked

A host that still runs locally built cloack/<svc> images is moved to the registry names with the /retag runbook (tag the running-good local image, never pull a registry copy that may be stale). ./start.sh deploy on a server host calls ff_pull_or_die, which resets the tree to origin/dev and removes untracked files: revert any path checkouts and move stray files first, or run with CLOACK_NO_AUTO_RESET=1.

A hybrid cluster (topology D below) has bare-metal compute nodes while the controller, login node, slurmdbd and slurmrestd run as containers of the stack (<cluster>-slurmctld, <cluster>-login01, <cluster>-slurmdbd, <cluster>-slurmrestd). The controller is configless; with SlurmCluster.manage_config off, the per-cluster mirror ${BASE_DATA}/slurm/<cluster>/slurm.conf is the source of truth.

4. Bare-metal Slurm via Ansible

cd /opt/cloack
./start.sh slurm ansible all                 # regenerate ansible/ tree
ansible-playbook -i ansible/clusters/<name>/inventory.ini \
  ansible/slurm-server/playbook.yml          # slurmctld + slurmdbd + slurmrestd
ansible-playbook -i ansible/clusters/<name>/inventory.ini \
  ansible/slurm-client/playbook.yml          # slurmd on every compute node
ansible-playbook -i ansible/clusters/<name>/inventory.ini \
  ansible/slurm-verify/playbook.yml          # read-only pre-flight (no changes)
./start.sh slurm prod-sim <name>             # ansible --check --diff, read-only

slurm-verify is safe to run any time and reports OS, UIDs 449/450, munge key, Slurm version, SPANK support, ports, SSSD cache TTL and the PAM stack. Compute nodes may be Rocky 9 or Debian-family (DGX Spark); the roles key the difference off ansible_os_family at run time.

Deploy pipeline

Step Host What you run Result
Code laptop ./start.sh deploy dev -y --paid-accounts, tests, git push origin dev Source on GitHub
Build validation host git pull, ./start.sh rebuild cloack/<svc>:latest built on amd64
Publish validation host ./start.sh publish ghcr.io/<org>/cloack/<svc>:dev + :sha-<short>
Validate validation host ./start.sh start --from-ghcr dev + bash scripts/verify-deploy.sh The published images run clean
Promote validation host ./start.sh promote :dev retagged :prod + :rc-<UTC> (same digest)
Deploy production host git pull, ./start.sh start --from-ghcr prod, verify-deploy.sh Stack on :prod
Rollback production host ./start.sh promote --rollback rc-<UTC> from the validation host, then start --from-ghcr prod Previous release candidate

Direction of artifacts:

git origin/dev                     GHCR registry
      ↓                                 ↓
laptop ──push──> origin          validation host ──push :dev, :sha-*, :prod, :rc-*──> GHCR
                                                                                      ↓
validation host ──pull──> origin production host ──pull :prod  (never pushes)
production host ──pull──> origin

GHCR registry namespace and PATs

Host PAT scope Operations
laptop none git push only
validation host GHCR_BUILDER_PAT (write) docker push :dev + :sha-*, :prod + :rc-*
production host GHCR_CONSUMER_PAT (read-only) docker pull :prod only

Registry path: ghcr.io/<org>/cloack/<image>:<tag>. Both PATs are fine-grained, scoped to the packages org, SSO-authorized for the institution, and rotated at most yearly (fine-grained PAT maximum lifetime).

Track Image Built from Published?

Two compose services share an image: qcluster runs coldfront, helpdesk-qcluster runs helpdesk (HELPDESK_ROLE=qcluster). munge-key, ood-sss-cache and keycloak-config are one-shot init containers; "Exited (0)" is their normal state.

Slurm topologies

SlurmCluster.cluster_type says where the compute runs, core_services where slurmdbd / slurmrestd run:

cluster_type core_services Scenario
container shared_container All-Docker cluster
bare_metal dedicated Bare-metal cluster with its own slurmdbd / slurmrestd
container dedicated Docker compute + external accounting
bare_metal shared_container Hybrid: bare-metal compute, controller + login + core in the stack

"Is there a container for this cluster on this host" is answered by core_services, never by cluster_type.

start.sh subcommands

Subcommand What it does
init [dev] Bootstrap user/group/dirs, write .env (appends missing keys only), install the backup cron on Linux hosts.
start [dev] Build (or skip build) and start managed services.
start --from-ghcr <dev / prod> Pull from GHCR, skip build. Refuses if docker-compose-ghcr.yml is missing.
stop / destroy / rebuild Stop; stop + remove containers (keeps volumes); rebuild every image with --no-cache.
deploy [dev] -y [--paid-accounts] [--no-slurm] Destructive: clean + init + start + Slurm + helpdesk + LDAP re-init + test data. Hard-refused with --from-ghcr.
publish [--tag <tag>] [--check] Retag local cloack/<svc>:latest as ghcr.io/...:<tag> + :sha-<short> and push. Refuses a dirty tree.
promote [--from <tag>] [--rc <label>] [--check] [--rollback <rc-tag>] [--skip-verify] Pull :dev, run verify-deploy.sh, retag + push :prod + :rc-<UTC>.
ldap-reinit [dev] Re-initialise OpenLDAP (restores migration/ldap-*.cat when present), force sync with ColdFront.
populate [dev] [--partitions ...] [--with-billing] Departments, rates, standard partitions / QoS, fake billing data.
slurm {create / start / stop / restart / rebuild / destroy / status / test-jobs / ansible / prod-sim} Per-cluster Slurm operations; ansible all regenerates the bare-metal scaffold.
helpdesk {start / stop / restart / status / destroy / log / populate} Helpdesk lifecycle. restart re-stages the code from the repo and migrates. populate seeds sample queues and hundreds of synthetic tickets: only for a throwaway installation.
ai {pull / start / stop / status / log} Local LLM engine: download the model, run the container.
mta {create / start / stop / restart / status / log} Postfix relay (my_cluster-mta): outbound smart-host relay or legacy inbound intake.
ood {start / stop / seed-apps / seed-config / ...} Open OnDemand: builds, seeds the host-bound app tree and config dir, starts.
wekafs-sync Append WEKAFS_* from wekafs.env into .env and recreate coldfront + qcluster.
clean [--all] Remove the stack's containers, volumes and images; --all also prunes orphans of other projects on the host.
test [module], test deploy, test status Django unit tests, the 16-phase integration test, container health.
log [service] Tail a service's logs.
doctor Read-only validation of .env, realm config, TLS cert and Host-header drift.
bash scripts/backup.sh pg_dumpall + slapcat + mysqldump into ${BASE_DATA}/backup/, 14-day retention (daily 00:30 via cron on Linux hosts).

Ansible playbooks

Playbook What it does When to run
ansible/slurm-server/playbook.yml Compiles Slurm from source, installs slurmctld / slurmdbd / slurmrestd on the controller groups Bare-metal install or major Slurm version bump
ansible/slurm-client/playbook.yml Same build stack plus slurmd on every compute node and login node (Rocky 9 or Debian-family) New compute node, or after slurm-server
ansible/slurm-verify/playbook.yml Read-only pre-flight (OS, UIDs, munge, Slurm version, SPANK, ports, SSSD TTL, PAM stack). No changes applied. Any time you want a confidence check
ansible/sssd-flush/playbook.yml Runs sss_cache -E on every login node sync_ldap already triggers this per cluster; manual run useful after a large LDIF import
cloack-deploy RPM The Ansible tree + a cloack-deploy CLI; per-cluster inventories fetched from the portal API Sites that prefer an RPM-driven flow over ansible-playbook directly

The static files behind the scaffold live in coldfront/custom/plugins/cloack_sync/ansible_scaffold_data.py; edit under ansible/, then python3 scripts/regen_ansible_scaffold.py.

Environment variables you will set on server hosts

Root .env is written by init and read by compose; coldfront.env and helpdesk.env are host-local, gitignored (skip-worktree on server hosts). An env_file change needs a container recreate, not a restart.

Variable Where Purpose
CLOACK_ENV coldfront.env prod arms the production guards: dev compose refused, Delete All hidden, manage_config cannot be enabled, Service Health container actions disabled.
CLOACK_TEST_BANNER coldfront.env True shows the yellow TEST ENVIRONMENT strip on a host that keeps CLOACK_ENV=prod (validation hosts).
CLOACK_SUPERUSERS .env Usernames promoted to Django superuser when they appear in LDAP cn=admin.
CLOACK_DOMAIN_OrgA, CLOACK_DOMAIN_ORGB .env Edge model: one host per service and org (portal., auth., helpdesk., ood. under each domain), routed by the in-stack NPM; drives realm selection on the portal and helpdesk login paths.
CLOACK_PUBLIC_HOST, KEYCLOAK_HOSTNAME_*, KC_HOSTNAME_BACKCHANNEL_DYNAMIC .env Public FQDNs behind the reverse proxy; Keycloak trusts X-Forwarded-Host when the backchannel flag is true.
KEYCLOAK_FEDERATION_CONVERGE_ENABLED coldfront.env Arms the hourly re-federation of broker-local campus ID rows (recreate qcluster).
HELPDESK_INTERNAL_TOKEN .env Shared secret of the ColdFront → helpdesk ticket bridge (both containers).
OOD_HOST_REGEX, OOD_GRAFANA_URL, OOD_ALLOWLIST_PATH .env OnDemand node proxy for Interactive Apps (no quotes), Grafana job-stats target, Files allowlist.
OOD_MEM_LIMIT, AI_MEM_LIMIT, SLURMRESTD_MEM_LIMIT .env Container memory caps (applied on recreate / slurm start).
MTA_MODE, MTA_RELAYHOST mta.env outbound relay through the campus smart host, or legacy inbound intake.
CLOACK_IMAGE_TAG, CLOACK_FROM_GHCR auto Set by --from-ghcr; override the tag only for a rollback.

Never put SLURM_CONF=<host path> into .env: it is an env_file of the containers and the path does not exist inside them. For a host shell, source scripts/loadenv.sh resolves it.

Troubleshooting

Symptom Likely cause Fix
Every Slurm client on the host hangs 60 s with s_p_parse_file: cannot stat file : SLURM_CONF= (empty) exported from .env by a wholesale set -a; . .env unset SLURM_CONF, or load the env with source scripts/loadenv.sh
Containers recreated by hand come up with wrong secrets or paths source base/base.config in the shell exported its ${VAR:-default} fallbacks, which compose prefers over .env Never source it before a manual compose; unset the BASE_*/OIDC*/LDAP_*/*_PASS* variables and --force-recreate only the affected services
start.sh aborts with "dev compose is forbidden on this host" CLOACK_ENV=prod and a dev argument (or the deploy auto-switch) Correct: server hosts use the base compose; CLOACK_FORCE_DEV=1 only on a throwaway box
/home or /scratch writes from sync_ldap vanish Containers were created from docker-compose-dev.yml (named volumes) on a server host verify-deploy.sh check 15 flags it; recreate from the base compose, then scripts/heal_scratch_links.sh --all
Parented Slurm account creates fail from the coldfront container The CLI shim cannot find the controller container Export SLURMCTLD_CONTAINER=<cluster>-slurmctld or let discovery match (^|-)slurmctld$; on bare-metal hosts SLURM_BIN is empty by design

deploy --from-ghcr is not allowed Validation and production hosts must never be populated with test data ./start.sh start --from-ghcr <tag> plus ./start.sh ldap-reinit

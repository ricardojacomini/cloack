Superuser — ColdFront / Django admin (cluster ops + identity)

Who you are + scope

You have is_superuser=True on your Django User. You typically also belong to the LDAP cn=admin group (cluster sudoers) and the helpdesk-admin group (helpdesk privileges). You approve / deny projects, allocations, storage and class requests, drain or resume Slurm nodes, manage users and PIs, reset stale OTP credentials, rotate the local /admin/ break-glass password, and read the qcluster audit log for every async task.

You typically also operate the cluster (deploy via start.sh, manage Ansible bundles): for that side read admin.md. For helpdesk-side work see staff.md. You authenticate via Entra federation if you use a campus ID; if you are an ext-* user you use TOTP via the Keycloak account console (same as every other regular user.md).

Staff who are not superusers get a subset of this through StaffResourceAssignment: elevate_to_superuser unlocks the review queues below (allocations, projects, storage, classes); cluster and affiliation scopes limit what they see.

Quick start

1. Approve / deny an allocation request

Admin Tools → Allocation Requests   (/allocation/request-list/)
  → "Approve" on the row, or open the allocation
/allocation/<id>/
  → review IO Number(s), spend cap, QoS pins, SubProject Scheme card
  → "Approve" / "Deny" (the deny reason is saved to the allocation description)

Approval triggers on_allocation_activated, which provisions the Slurm account hierarchy in real time. The ToS gate still applies: a user association is created only for users who accepted the current ToS.

Two gates on Approve:

  • Slurm account-name conflict: another live allocation of the same project resolves to the same account name (a second allocation without a SubProject suffix). Approve is disabled on the row and refused on POST until you set the suffix on the SubProject Scheme card. Suffixes are never assigned automatically.
  • Spend cap not set (Weekly Cap ($) = 0): the allocation activates, but its account is held (GrpSubmitJobs=0) until the PI or you set a cap or click No cap on Allocation Detail.

1b. Review a new project, a storage request, a class request

Admin Tools → Project Reviews   (/project/project-review-list)
  → Activate | Request changes (feedback required; the PI resubmits by saving the project)
    | Deny (archived with the reason; the PI may Reopen & resubmit)
  → Delete: superusers only, for projects that were never activated
Admin Tools → Storage Review    (/staff/storage-review/)
  → Approve | Approve (override cap) | Deny; "Edit Provisioned" on the project card
    sets the provisioned values directly
Admin Tools → Class Requests    (/staff/class-review/)
  → resolve the department ("Other" needs Create or Map), fix the course code if needed,
    Approve (creates project, allocation and the <code>-ext-<campus-id> accounts) | Request changes | Deny

Project Reviews also lists Billing Changes Pending Review (an IO Number changed on Update Project): "Approve Changes" clears the flag.

1c. Delete an allocation (superuser only)

/project/<id>/      → trash icon on the allocation row
/allocation/<id>/   → "Delete Allocation…" card
  → confirmation page lists what goes with it
    (Slurm account, active members, billing usage rows, IO links, open tickets)
  → "Confirm — Delete Allocation"

Any status can be deleted except the default project's allocation (its bare <pi> Slurm account belongs to the promote / demote flow). Staff, even with elevate_to_superuser, and PIs do not get the button; they click Request Deletion on Allocation Detail instead, which opens a helpdesk ticket in their name and shows a "Deletion requested … ticket #N" alert on the allocation (with the Delete button for you). Deleting writes an admin log entry and resolves that ticket. The orphaned Slurm account is removed by the next scheduled full sync (≤15 min); jobs still running under it block that removal: check squeue -A <account> first.

2. Drain / resume a Slurm node

Clusters → All Clusters → <cluster>   (/cluster/)
  → node table → "Drain" (reason required) / "Resume"

The action goes to slurmrestd for the right cluster (CLI fallback on container clusters) and is available to superusers and to staff with that cluster in their Cluster Scope. Django Admin › Slurm Clusters offers the cluster-level actions instead: Deploy / Stop / Restart / Build images (container clusters), Apply shares, Import from slurmrestd, Update from slurmrestd, Check drift.

3. Manage users and PIs

Admin Tools → Manage Users   (/user/staff-manage-users/)
  → toggle PI, clear a pending PI request, assign Cluster / Affiliation scope
Admin Tools → Promote to PI  (/user/staff-promote-pi/)
Admin Tools → Import Users   (/billing/import-users/)
  • Promote creates the default project (in the primary department the user chose), its scavenger allocation, the LDAP PI group and the Slurm account. Demote (the same toggle, with a confirm dialog) tears all of that down again (project archived, allocations expired, bare account and LDAP group removed, shell recomputed; home and scratch kept) and is refused while the PI owns non-archived paid projects. Flipping is_pi in Django Admin does not run the teardown.
  • Import Users handles CSV imports (new accounts with reset e-mails), LDIF migration imports with a duplicate-resolution preview, an approved class from a roster (course mode), Export Users CSV, and course-account teardown.
  • Login shell: /bin/bash only for admins and for users sponsored by a PI who accepted the ToS; the per-user "Disable login shell" checkbox on the profile forces /bin/false through every sync.
  • Delete All on Manage Users exists only on hosts running with CLOACK_ENV=dev.

4. Reset a stale OTP credential

docker exec keycloak bash -c '/opt/keycloak/bin/kcadm.sh ...'

See the recipe in keycloak/README.md "Clear a stale OTP credential". It requires:

  • kcadm config credentials once per session (writes /tmp/kcadm.config).
  • kcadm get users -q username=$USER to fetch the user id.
  • kcadm delete users/$UID/credentials/<cred-id> to drop the OTP row.

Alternative, force the user to re-enrol on their next login:

kcadm update users/$UID --config /tmp/kcadm.config -r orga \
  -s 'requiredActions=["CONFIGURE_TOTP"]'

5. Rotate the break-glass /admin/ password

bash scripts/rotate-admin-password.sh

Generates a 32-char password, applies it via changepassword inside the coldfront container, appends an entry to the gitignored audit log, and prints the password once for paste into the team vault. See docs/break-glass-admin.md for the full runbook (vault location, quarterly rotation cadence, admin_login_alert_task alert wiring).

6. Maintenance mode

Admin → Site Configuration → Maintenance: maintenance_mode shows the announcement banner (message + severity) on the portal and every page; maintenance_hide_actions hides the login buttons and the helpdesk card on the landing page; maintenance_lockout serves a 503 page to everyone who is not staff (admins keep signing in through /admin/ and the SSO paths, healthchecks and the /api/v1/maintenance/ poll stay open). The three toggles are independent.

7. Read the qcluster audit trail

/admin/django_q/task/
/admin/?app=admin&model=logentry   → Home → Administration → Log entries
Admin Tools → Audit Trail          (/staff/audit-trail/)

Every async_task() call uses the task_completion_hook so the admin LogEntry table records when each scheduled task ran, success or failure, duration, and result snippet.

Reference matrices

Scheduled tasks (django-q)

Task Schedule Purpose
sync-ldap-daily 02:00 daily Full LDAP sync (PIs, members, groups, home dirs, scratch and project symlinks, login shells).
sync-slurm every 15 min Safety net for the signal-based real-time provisioning.
collect-sacct-periodic every 15 min Pull completed jobs into SlurmJob, 1-day lookback (shallow).
collect-sacct-deep 02:45 daily Same import over a 7-day window; heals late accounting updates.
check-core-hours-reset 01:00 daily Zero the ColdFront usage gauges on the scheduled reset date (never touches Slurm).
reconcile-overdue-io-pauses 04:15 daily Apply the overdue-invoice pause once the grace window elapsed; status changes reconcile immediately.
flag-ended-classes 04:30 daily Mark classes past their end date as Ended and open one teardown ticket each.
cleanup-task-queue hourly :30 Purge stuck / old qcluster tasks.
sync-totp-status every 30 min Mirror Keycloak TOTP enrolment state into UserProfile.totp_enrolled.
converge-keycloak-federation hourly :40 Re-federate broker-local campus ID Keycloak rows; returns SKIP unless KEYCLOAK_FEDERATION_CONVERGE_ENABLED=True.
refresh-slurm-jwt every 6 h (:17) Re-issue the slurmrestd JWT (file + SlurmCluster.jwt_token).
renew-service-api-tokens 03:00 daily Slide the created date of the service API tokens so the helpdesk's key never expires.
sync-bare-metal-topology every 10 min import_slurm_cluster --update per bare-metal cluster (nodes, partitions, usage reset period).
rotate-admin-log monthly Archive, then purge, admin log entries older than the retention window.

Adding or changing a task needs docker restart coldfront qcluster: the worker caches the task module at start.

LDAP privilege groups (per affiliation tree)

Group UID/GID What it grants
cn=admin,ou=Groups,ou=<aff> reserved Cluster sudoers; sudo on every Slurm node. Members are imported as Django is_staff=True + the "Cluster (LDAP admin)" group at first deploy.
cn=helpdesk-admin,ou=Groups,ou=<aff> per affiliation Helpdesk admin (manage queues, change ticket status, edit categories).
cn=helpdesk-staff,ou=Groups,ou=<aff> per affiliation Helpdesk staff (work tickets, classify, reply).
Cluster (LDAP admin) Django Group n/a Source of cn=admin membership: manage at /admin/auth/group/; the m2m_changed signal publishes to LDAP and every sync reconciles.
CLOACK_SUPERUSERS env var n/a Comma-separated usernames promoted to is_superuser=True when they appear in cn=admin.

User.is_staff / is_superuser are decoupled from cn=admin: toggling them never changes LDAP.

Scope M2M target Controls

Per-allocation controls on Allocation Detail

Control Who Effect
Weekly Cap ($) / Weekly Cap (SU) + No cap PI, staff Spend cap on the account association; 0 = held, −1 = none
QoS / DefaultQoS staff Pin the account's QoS list / default (condo, class, elevated GPU tier); blank = cluster default for the account class; enforced by every sync
SubProject Scheme card staff, not on Active Set the account suffix (<pi>_<proj>_A); the only way to resolve an account-name conflict
IO Assignment card staff, PI Pay links; the last pay link cannot be removed; paused / inactive IOs refused as new links
Sync Now staff Immediate per-allocation Slurm sync

Troubleshooting

Symptom Likely cause Fix
Allocation approved but Slurm account not created ToS not accepted by the PI, no pay IO (account frozen), or on_allocation_activated raised Check the Log entries and TOSAcceptance; docker exec coldfront coldfront sync_slurm --dry-run previews what the sync would do
Approve button disabled on an allocation Slurm account-name conflict with another allocation of the project Set the SubProject suffix on the scheme card, then approve
Users on a paid account cannot submit (AssocGrpSubmitJobs) Cap unset (0) or every pay IO paused Set a cap / No cap; resume the IO (Billing Management → IO Numbers shows all)
/admin/ login alert email not received CLOACK_ADMIN_ALERT_EMAILS not set in .env, or the recipient filtered it Set the env var; check the admin_login_alert_task LogEntry
cn=admin membership change not visible on a login node SSSD cache; sss_cache -E runs at the end of every sync, TTL 60 s Wait a minute, or run sss_cache -E on the node; an already-open shell keeps its old group list until re-login
New user created but no UserProfile The Postgres trigger tr_auth_user_after_insert_fn lacks a NOT NULL column added later Re-run coldfront/init/ldap_sync_postgres_run_it_once.py; ship new NOT NULL columns with the trigger + SET DEFAULT migration
Scheduled task missing from qcluster Schedule added but the worker not restarted docker restart coldfront qcluster
OTP re-enrol flow does not prompt User has no CONFIGURE_TOTP required action Use the kcadm update users snippet from Quick start §4
helpdesk-admin LDAP membership changed but the Django group did not LDAP → Django is reconciled by the sync, not by a signal docker exec coldfront coldfront sync_ldap
Allocation stays New for a staff member Staff scope does not include the requesting affiliation Add the affiliation to the staff's StaffResourceAssignment, or escalate to a superuser
A partition users should not see keeps coming back after deletion The 10-minute topology import recreates rows the controller reports Uncheck is_available instead of deleting
